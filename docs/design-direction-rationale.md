# Pacto 디자인 방향성 근거

## 선택한 방향

Pacto의 전체 디자인 방향은 `Toss Office + Creator Friendly` 조합으로 잡는다.

- 광고주 Dashboard: 업무용 운영 콘솔에 가깝게 만든다.
- 블로거 App: 캠페인 탐색, 미션 수행, 보상 확인이 쉬운 모바일 앱 경험으로 만든다.

두 화면은 같은 브랜드 안에 있지만 사용자의 목적이 다르다. 따라서 색상, 타이포그래피, 상태 표현은 공유하되 정보 밀도와 화면 리듬은 다르게 가져간다.

## 왜 이 방향인가

### 1. 광고주는 반복 업무를 빠르게 처리해야 한다

광고주가 Dashboard에서 하는 일은 감상보다 판단에 가깝다.

- 캠페인 상태 확인
- 지원자 승인/반려
- 미션 검수
- 에스크로/정산 확인
- 예산 관리

따라서 Dashboard는 큰 장식보다 숫자, 상태, 테이블, 액션 버튼이 먼저 보여야 한다. 카드형 UI는 사용하되 마케팅 페이지처럼 느슨하게 펼치지 않고, 업무 도구처럼 촘촘하고 예측 가능하게 배치한다.

### 2. 블로거는 “할 만한 캠페인”과 “받을 보상”이 먼저 보여야 한다

블로거 App에서 중요한 판단 기준은 다음이다.

- 이 캠페인을 신청할 가치가 있는가
- 보상은 얼마인가
- 언제까지 제출해야 하는가
- 지금 내가 해야 할 다음 행동은 무엇인가

그래서 블로거 화면은 모바일 앱처럼 상단 요약, 보상 강조, 상태별 카드, 고정 CTA를 적극적으로 사용한다. 광고주 화면보다 조금 더 친근하고 보상이 잘 보이게 한다.

### 3. 한 브랜드 안의 다른 밀도

Dashboard와 Blogger App을 완전히 같은 UI로 만들면 둘 중 하나가 어색해진다.

- Dashboard를 너무 앱처럼 만들면 업무 밀도가 떨어진다.
- Blogger App을 너무 콘솔처럼 만들면 참여 동기가 약해진다.

따라서 공통 원칙은 유지하되 화면별 밀도를 다르게 둔다.

공통 원칙:

- 파란색은 주요 액션과 긍정적 진행 신호에 사용한다.
- 녹색은 승인/정산 완료에 사용한다.
- 빨간색은 취소/반려/위험 신호에 사용한다.
- 카드 radius는 8px 기준으로 유지한다.
- 긴 설명보다 상태와 액션을 우선한다.

## 현재 반영한 내용

### Dashboard

- 배경을 더 밝게 조정해 업무용 콘솔 느낌을 강화했다.
- 카드와 KPI에 낮은 그림자를 추가해 정보 그룹을 더 잘 구분한다.
- 대시보드 메인 그리드는 캠페인, 예산, 콘텐츠, 블로거, 정산 영역이 명확히 나뉘도록 유지한다.
- 카드 내부는 숫자와 상태가 먼저 보이도록 구성한다.

### Blogger App

- 캠페인 목록 상단에 모집 수, 평균 보상, 마감 임박 수를 추가했다.
- 캠페인 화면의 안내 문구를 “보상만 보지 말고 일정에 맞게 고르기”로 조정했다.
- 미션 페이지 상단에 진행 중 미션, 예상 보상, 승인 대기 수를 추가했다.
- 미션 보드에 “다음 행동” 패널을 추가해 사용자가 바로 할 일을 알 수 있게 했다.

## 아직 백엔드 데이터가 필요한 부분

현재 일부 데이터는 프론트 계산 또는 목업이다.

- 캠페인 카테고리
- 블로거 프로필 이미지
- 블로거 평균 등급
- 캠페인별 정확한 브랜드/카테고리 메타
- 포인트 내역의 캠페인명
- 대시보드 홈 전용 recentCampaigns

이 값이 API 계약에 추가될 때는 `packages/api`의 adapter와 `packages/types`의 도메인 타입을 함께 갱신한다.

## 앞으로의 디자인 판단 기준

새 UI를 추가할 때는 다음 질문을 기준으로 결정한다.

- 광고주 화면인가, 블로거 화면인가
- 사용자가 지금 판단해야 하는 값은 무엇인가
- 다음 행동 버튼이 명확한가
- 상태 색상이 도메인 의미와 일치하는가
- 없는 데이터를 프론트에서 꾸며내고 있지 않은가

이 기준을 따르면 Pacto는 MVP 단계에서도 화면마다 목적이 분명하고, 추후 백엔드 DTO가 확장되어도 UI 구조를 크게 갈아엎지 않아도 된다.
