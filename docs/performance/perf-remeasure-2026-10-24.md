# Pacto 블로거 앱 성능 재측정 결과

측정일: 2026-10-24

측정 대상은 2026-10-24 당시의 로컬 작업 트리입니다. 폰트 지연 적용 코드는 후속 커밋으로 반영했으며, 목업 API 등 다른 로컬 변경은 이 저장소 변경에 포함되지 않습니다.

## 결론

- 이력서 성능 bullet은 **전송량·요청 수 지표**로 쓴다. 이 값들은 환경과 무관하게 재현된다.
- **로컬 프론트 + 실서비스 API 조건의 7월 LCP와 로컬 목업 Lighthouse 점수를 하나의 전후 비교로 섞지 않는다.** 당시 API 서버와 DB가 종료돼 7월 측정 조건을 재현할 수 없다. 아래 로컬 프로덕션 빌드의 동일 조건 비교는 별도 사례로 제시한다.
- 7월의 로컬 프론트 + 실서비스 API 조건에서 측정한 7.9초·7.5초는 **문제 정의용**으로만 쓴다.

## 쓸 수 있는 수치

| 항목                               | 개선 전 |        개선 후 |
| ---------------------------------- | ------: | -------------: |
| `/campaigns` 첫 화면 이미지 전송량 | 2,519KB |   207KB (−92%) |
| `/missions` 첫 화면 이미지 전송량  | 2,469KB |   125KB (−95%) |
| `/campaigns` 페이지 총 전송량      | 3,057KB | 1,069KB (−65%) |
| 탭 재방문 시 네트워크 요청         |     1건 |            0건 |
| 탭 재방문 시 API 호출              |   1~5회 |            0회 |
| 5개 탭 순회 시 API 호출 합계       |    17회 |    11회 (−35%) |

- 5개 탭 순회 순서: 캠페인 → 미션 → 지갑 → 캠페인 → 미션
- 정적 이미지 원본 용량: 6개 에셋 2.80MB → 0.18MB (PNG → WebP 전환)

문제 정의용 실측값(2026-07-13, 로컬 프론트 + 실서비스 API, 개선 전):

- 블로거 핵심 화면 평균 LCP 7.5초, 평균 성능 점수 49점
- `/campaigns` LCP 7.9초

## 재측정으로 회귀를 찾아 수정한 사례 (`/campaigns`)

| 단계                        | 성능 점수 |       FCP | Speed Index |       LCP |
| --------------------------- | --------: | --------: | ----------: | --------: |
| 개선 전 (`6bef992`)         |        67 |     3.3초 |       3.3초 |     7.9초 |
| 개선 후, 폰트 회귀 상태     |        64 |     4.9초 |       4.9초 |     7.0초 |
| 폰트를 load 이후 적용       |        76 |     0.9초 |       1.5초 |     7.2초 |
| 폰트를 LCP 이후 적용 (최종) |    **86** | **0.9초** |   **1.6초** | **4.2초** |

표의 각 값은 지표별 3회 측정 중앙값입니다. 아래 요약 캡처는 LCP 중앙값과 일치하는 회차여서 다른 지표는 표의 중앙값과 다를 수 있습니다.

- 회귀 원인: 7/28 커밋 `99226dd`에서 외부 CDN SUIT 가변 폰트(610KB)를 `@import`로 추가했다. `font-display`가 없어 폰트가 도착할 때까지 텍스트가 그려지지 않았다.
- 1차 수정: `next/font/local`로 셀프 호스팅하고 `display: swap`을 적용했다. FCP가 4.9초 → 4.1초로 줄었지만, 폰트가 여전히 첫 화면 다운로드와 대역폭을 다퉜다.
- 2차 수정: 첫 화면은 시스템 폰트로 그리고, `load` 이후에 SUIT를 적용했다. FCP는 0.9초가 됐지만 LCP는 7.2초로 그대로였다.
  - 원인: 스트리밍 렌더링 때문에 `load`(139ms)가 LCP(592ms)보다 먼저 끝났다. 그래서 폰트(610KB)가 여전히 LCP 전에 다운로드됐고, LCP 이전 전송량의 57%를 차지했다.
- 3차 수정: `PerformanceObserver`로 LCP 후보가 1초간 더 나오지 않으면 SUIT를 적용한다. 사용자가 화면을 누르면 즉시 적용하고, 최대 5초 안에는 반드시 적용한다. 그 결과 LCP 4.2초를 달성했다.
- 트레이드오프:
  - 첫 방문 시 시스템 폰트에서 SUIT로 한 번 바뀌는 깜빡임이 있다.
  - CLS가 0 → 0.017로 늘었다. 기준치(0.1) 이내다.
- 캡처: [개선 전 Lighthouse 요약](./evidence/2026-10-24/p5-lighthouse-summary-before.png), [개선 후 Lighthouse 요약](./evidence/2026-10-24/p5-lighthouse-summary-after.png)
  - 3회 측정 중 LCP 중앙값과 일치하는 회차를 사용했다.
  - after 썸네일에 보이는 모달은 첫 방문 시 뜨는 PWA 설치 안내다.

## 측정 조건 (포트폴리오 "검증 결과"에 함께 표기)

- 개선 전: 커밋 `6bef992`(2026-07-13 기준선). 개선 후: 2026-10-24 당시 로컬 작업 트리
- 두 버전 모두 로컬 프로덕션 빌드(`next build` + `next start`)에 동일한 mock API 데이터 사용
- Lighthouse 12.8.2 모바일 기본 프리셋(simulate 스로틀링: RTT 150ms, 1.6Mbps, CPU 4배 감속)
- Lighthouse는 화면당 3회 측정한 중앙값
- 요청 수는 headless Chrome(412×823 모바일 뷰포트)에서 측정. 2회 반복해 같은 값 확인
