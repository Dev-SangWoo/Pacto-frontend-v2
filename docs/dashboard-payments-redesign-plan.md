# 대시보드 결제/지갑 페이지 수정 계획

## 방향

대시보드 결제/지갑 페이지는 충전/출금 폼을 크게 보여주는 페이지가 아니라, 광고주가 예산 상태를 관제하는 화면으로 구성한다.

충전과 출금은 주요 액션이지만 페이지의 본문 정보는 아니다. 따라서 충전/출금은 버튼과 모달로 이동시키고, 본문은 잔액, 잠긴 예산, 정산/환불 흐름, 최근 포인트 내역을 중심으로 구성한다.

## 핵심 질문

광고주가 이 페이지에서 확인해야 하는 것은 다음이다.

- 지금 사용할 수 있는 잔액은 얼마인가?
- 캠페인 때문에 잠긴 금액은 얼마인가?
- 정산 완료/환불 처리된 금액은 얼마인가?
- 최근 어떤 이유로 포인트가 움직였는가?
- 충전 또는 출금은 어디서 빠르게 실행할 수 있는가?

## 1차 구현 범위

현재 백엔드 API로 안정적으로 구현 가능한 범위부터 적용한다.

사용 API:

- `GET /api/v1/wallets/me`
- `GET /api/v1/wallets/me/histories`
- `GET /api/v1/advertiser/dashboard`

구성:

1. 상단 잔액 요약 카드
   - 사용 가능 잔액
   - 잠긴 예산
   - 정산 완료 금액
   - 환불/취소 금액

2. 예산 분포 막대
   - 사용 가능
   - 잠긴 예산
   - 정산 완료
   - 환불/취소

3. 최근 포인트 흐름 타임라인
   - 충전
   - 예산 잠금
   - 정산
   - 환불
   - 출금

4. 충전/출금 액션 모달
   - `충전하기` 버튼 클릭 시 충전 모달
   - `출금 신청` 버튼 클릭 시 출금 모달

## 2차 구현 범위

백엔드에 캠페인별 에스크로/예산 API가 추가되면 적용한다.

필요 API:

```http
GET /api/v1/advertiser/campaigns/{campaignId}/escrows
GET /api/v1/advertiser/campaigns
```

추가 구성:

- 캠페인별 예산 현황 테이블
- 캠페인별 총 예산
- 캠페인별 잠긴 예산
- 정산 완료 금액
- 환불 가능/환불 완료 금액
- 예산 소진률 progress bar

## 시각화 기준

### 숫자 카드

잔액과 예산 상태는 숫자가 가장 중요하므로 카드 형태로 빠르게 스캔 가능하게 배치한다.

### Stacked Bar

도넛 차트보다 가로 누적 막대가 더 적합하다.

이유:

- 금액 비율 비교가 쉽다.
- 지갑 화면은 장식보다 정확한 비교가 중요하다.
- 모바일에서도 세로 공간을 적게 쓴다.

### Timeline

최근 포인트 내역은 테이블보다 타임라인이 적합하다.

이유:

- 돈의 흐름을 시간순으로 이해하기 쉽다.
- `+/-` 금액과 타입 라벨을 함께 보여주기 좋다.
- 관련 캠페인/결제 링크가 생기면 확장하기 쉽다.

## 현재 제약

- 포인트 히스토리에는 캠페인명/블로거명이 없다.
- 에스크로 응답에는 캠페인명/블로거명이 없다.
- 광고주 캠페인별 에스크로 목록 API가 없다.

따라서 1차 구현에서는 referenceId와 타입 중심으로 보여주고, 조인 필드가 추가되면 캠페인명과 블로거명을 표시한다.
