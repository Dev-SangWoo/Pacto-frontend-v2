# 블로거 캠페인 목록 화면 한정 리디자인

## 목표

블로거가 캠페인 목록에서 보상, 마감, 신청 현황, 수행 미션을 빠르게 비교하고 상세 화면으로 진입할 수 있도록 모바일 목록 화면을 재구성한다. 백엔드 API와 상세 페이지 이동 흐름은 유지하고, `/campaigns` 목록 화면과 그 화면에서 사용하는 앱바 표현만 변경한다.

## 범위

### 포함

- `/campaigns` 전용 상단 앱바 표현과 실제 검색 동작
- 프로모션 배너와 제공된 여성 일러스트 배치
- 가로 스크롤 단일 선택 카테고리 필터
- 단일 열 캠페인 카드, 상태 배지, 지표, 미션 패널, CTA
- 모바일 하단 탭에 가리지 않는 목록 하단 여백
- 로딩 실패 및 필터 결과 없음 상태의 새 시각 언어 적용
- 캠페인 화면 내부로 제한한 디자인 토큰

### 제외

- 캠페인 상세 페이지 재설계
- 미션, 지갑, 프로필, 로그인 화면의 전역 스타일 교체
- API 계약 또는 전역 상태관리 구조 변경
- 찜 API가 없는 상태에서의 가짜 찜 기능
- 캠페인 생성 시각이 없는 상태에서 임의로 `신규`를 표시하는 로직

## 선택한 접근

화면 한정 리디자인을 적용한다. 기존 서버 컴포넌트의 데이터 조회와 클라이언트 카테고리 필터를 유지하면서, `CampaignExplorer`의 마크업과 캠페인 전용 CSS를 교체한다. 공유 앱바는 현재 경로가 `/campaigns`일 때만 캠페인 제목과 검색 동작을 제공하고 다른 화면에서는 기존 표현을 유지한다.

이 접근은 전역 토큰 교체보다 회귀 범위가 작고, 별도 디자인 시스템 구축보다 현재 요청에 적절한 규모다.

## 화면 구조

1. 높이 약 52px의 앱바
   - 왼쪽: 기존 Pacto 브랜드 자산을 사용한 24px 마크와 `캠페인` 제목
   - 오른쪽: 알림과 검색 버튼, 각 최소 44px 터치 영역
   - 읽지 않은 알림은 7px 빨간 점으로 표시
2. 높이 112px의 프로모션 배너
   - 왼쪽: `내 블로그로 / 브랜드를 소개하고 / 보상을 받아보세요!`
   - 오른쪽: `assets/woman-social-tablet-hd-transparent-refined.png`
   - 구현 시 웹 제공 경로인 `apps/blogger/public/illustrations/`에 복사
3. 추천 캠페인 헤더
   - 왼쪽: `추천 캠페인`
   - 오른쪽: 필터 결과 건수 또는 `전체 보기 ›`
4. 가로 스크롤 카테고리 필터
   - `전체 / 일상·리뷰 / 여행 / 뷰티 / 푸드 / IT·기기`
   - 단일 선택, 선택 상태는 컴포넌트 로컬 상태
5. 단일 열 캠페인 목록
   - 80×80px 썸네일과 요약 정보
   - 상태 배지, 제목, 설명, 보상·마감·신청 현황
   - 하단 연한 파란 미션 패널과 전체 폭 CTA
6. 하단 안전 여백
   - 마지막 캠페인의 CTA가 고정 하단 탭 위까지 완전히 스크롤되도록 확보

## 디자인 토큰

캠페인 화면 최상위 요소에 다음 CSS 변수를 선언해 다른 화면으로 전파되지 않게 한다.

- Primary: `#1478F5`
- Primary pressed: `#0967DD`
- Promotion background: `#F0F6FF`
- Mission background: `#F3F7FF`
- Text: `#182033`
- Secondary text: `#8A94A6`
- Inactive icon: `#A9B2C0`
- Border: `#E8EDF3`
- New: `#4798FF`
- Active: `#36C995`
- Closing: `#FFB85C`
- Notification: `#FF4D5E`

글꼴은 기존 Pretendard 스택을 유지한다. 제목 18/24px 700, 캠페인 제목 14/20px 700, 설명 12/18px 400, 필터와 버튼 13/18px 600을 기준으로 한다.

## 컴포넌트 변경

### `CampaignExplorer`

- 기존 2열/목록 보기 토글과 요약 지표형 히어로를 제거한다.
- 프로모션 배너, 카테고리 칩, 새 카드 목록을 렌더링한다.
- 검색어는 URL의 `q` 값으로 서버에서 1차 필터하고 카테고리는 클라이언트에서 2차 필터한다.
- 기존 localStorage 기반 플로팅 안내는 프로모션 배너와 역할이 겹치므로 제거한다.

### 캠페인 카드

- 카드 전체를 하나의 중첩 링크로 만들지 않는다. 정보 영역의 상세 링크와 CTA 링크를 분리해 유효한 인터랙션 구조를 유지한다.
- 찜 기능은 데이터/API가 없어 표시하지 않는다. 추후 API가 생기면 독립 버튼으로 추가한다.
- 배지는 마감까지 7일 이하면 `마감 임박`, 그 외 모집 중 캠페인은 `진행중`으로 표시한다.
- `신규` 토큰은 준비하되 생성일 데이터가 없어 현재는 사용하지 않는다.
- 설명과 미션 문구는 `guidelines` 문자열에서 사람이 읽을 수 있는 첫 문장을 추출하고, 값이 비어 있으면 안전한 기본 문구를 사용한다.
- 신청 현황은 `applicantCount / totalSlots`, 보상은 기존 포인트 포맷, 마감은 기존 D-day 유틸리티를 사용한다.

### 앱바 검색

- `/campaigns` 루트에서 검색 아이콘을 누르면 앱바 아래 검색 입력을 연다.
- 제출 시 `q` 검색 파라미터로 이동하며 캠페인명, 브랜드명, 가이드 문구를 기준으로 필터링한다.
- 다른 경로에서는 기존 앱바와 프로필 진입 동작을 유지한다.

## 데이터 흐름

1. 서버 페이지가 기존 API로 모집 중 캠페인을 조회한다.
2. `q`가 있으면 서버에서 검색 조건을 적용한다.
3. 필터된 캠페인과 오류 메시지를 `CampaignExplorer`에 전달한다.
4. 사용자가 카테고리를 선택하면 클라이언트 로컬 상태로 즉시 필터링한다.
5. 카드 CTA 또는 상세 링크는 기존 `/campaigns/[campaignId]`로 이동한다.

API 호출, 세션 쿠키, 서버 액션, 전역 상태관리 방식은 변경하지 않는다.

## 반응형 및 접근성

- 기준 폭은 기존 430px 모바일 셸이며 360px 이하에서도 80px 썸네일과 정보 영역이 겹치지 않게 한다.
- 앱바 아이콘과 CTA는 최소 44px 터치 영역을 제공한다.
- 카테고리는 `aria-pressed`, 검색 토글은 `aria-expanded`, 알림 점은 읽을 수 있는 레이블을 제공한다.
- 텍스트 말줄임은 제목 1줄, 설명 최대 2줄로 제한한다.
- 장식용 배너 이미지는 빈 대체 텍스트를 사용하고 문구 정보는 실제 텍스트로 유지한다.
- 키보드 포커스 스타일과 `prefers-reduced-motion` 설정을 존중한다.

## 오류 및 빈 상태

- API 오류가 있으면 캠페인 카드 대신 기존 오류 메시지를 캠페인 토큰에 맞춘 빈 상태로 표시한다.
- 검색 또는 카테고리 결과가 없으면 필터를 바꾸도록 안내하고 `전체 보기` 동작을 제공한다.
- 이미지 URL이 없거나 로드되지 않으면 기존 로컬 캠페인 썸네일을 사용한다.

## 검증

- TypeScript 타입 검사와 ESLint를 실행한다.
- 카테고리 분류, 배지 분류, 가이드 문구 추출처럼 순수 로직은 단위 테스트 대상으로 분리한다.
- 로컬 블로거 앱에서 430px와 360px 뷰포트를 확인한다.
- 앱바 검색 열기, 검색 제출, 칩 단일 선택, 카드 상세 이동, CTA 상세 이동을 직접 확인한다.
- 마지막 카드 CTA가 하단 탭에 가리지 않는지 확인한다.
- `/missions`, `/wallet`, `/profile`의 앱바와 레이아웃이 기존대로 유지되는지 회귀 확인한다.
